# Enshait model — context for LLM chats

Use this text (or an excerpt) as **system or user context** when discussing the simulation deployed at **enshait.metakarma.org** (GitHub: **metakarma/enshaittify**, package path **agentic-web-sim**).

---

The **Enshait** model is a **discrete-time stock–flow simulation** of how the **agentic web** might split between **open, commons-aligned** signal processing (protocols, data unions, FIDU-like stewards loyal to users) and **centralised platform** signal processing. The **total addressable market (TAM)** is normalised to **one**; time runs in **monthly steps for eight years**, while structural equations use **calendar time** $t$ in **years** (96 steps). The implementation is a **Streamlit** app with adjustable parameters and Plotly charts.

**Stocks and heterogeneity.** Adopters are divided into **four consumer types** with configurable population weights. Each type has its own **shifted Bass** arrival schedule (innovation/imitation parameters and a target peak year), and its own utility coefficients on signal quality, network size, lock-in, enshittification, agent friction relief, and values premium. For each type $i$ the model tracks **open-side stock** and **platform-side stock**; **$N_{\mathrm{open}}$** and **$N_{\mathrm{platform}}$** are their sums over types—cumulative **shares of TAM** on each architecture.

**Within a month**, new entrants arrive; before a **platform entry delay** (in months), all arrivals join the open side. After platforms exist, entrants choose open vs platform via a **logit** with inverse temperature **λ**. Existing adopters may **switch** once per month using separate logit probabilities with **asymmetric leave costs** per type. Utilities depend on **commons signal quality** $Q_{\mathrm{open}}$ (rising with institutional maturity **$F(t)$** and $\ln(1+N_{\mathrm{open}})$) and **platform signal quality** $Q_{\mathrm{platform}}$ (rising with $N_{\mathrm{platform}}$ via a sigmoid, minus **enshittification** drag). **Lock-in** $L$ accumulates when platform **share among adopters** exceeds a **dominance** threshold; **$E(t)$** (enshittification) turns on when that same among-adopters share crosses an **enshittification threshold**, with a **time ramp** and a **competitive brake** that weakens $E$ when the open ecosystem remains large. **$A(t)$** captures AI reducing friction for open protocols; **$V(t)$** a values/autonomy premium for the open side.

**How to read headline outputs.** “**Open share (cumulative)**” is **$N_{\mathrm{open}}$** at $t=8$ as a fraction of TAM—not conditional on adopting. “**Platform share among adopters**” is **$N_{\mathrm{platform}}/(N_{\mathrm{open}}+N_{\mathrm{platform}})$**, i.e. the split among people who adopted either architecture. “**Peak enshittification**” is **$\max_t E(t)$**. The model is **illustrative**: it compresses a contested future into a small equation set; results depend strongly on sliders such as **$k_F$** (speed of institutional maturity), platform baseline quality, **$A_{\max}$**, and the enshittification threshold.

**Outputs and presets.** The simulation writes a **monthly dataframe** (e.g. $N_{\mathrm{open}}$, $N_{\mathrm{platform}}$, $Q_{\mathrm{open}}$, $Q_{\mathrm{platform}}$, $F$, $L$, $E$, $A$, $V$, arrival and switching flows). The UI includes **scenario presets** that bundle a few narrative lever settings; everything else stays on the user’s current sliders unless changed. **No calibration to real market data** is claimed—the goal is comparative statics and structured debate, not forecasting. Equations are implemented in Python (**`app/model.py`**, **`app/dynamics.py`**, **`app/consumer_types.py`**) and summarised in the app’s expandable model notes. Production runs in **Docker** behind **nginx**; local use is `streamlit run app/main.py`. Ask the user which **parameter set** or chart they care about before inferring detailed numbers.
